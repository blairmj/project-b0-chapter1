# PROJECT B-0 V1 · 연구소 탈출

**초등학교 5~6학년을 위한 AI 교육용 1인칭 퍼즐 어드벤처.**

폐쇄된 AI 교육 연구소에서 깨어난 아이가 모르는 것이 많은 AI 로봇 B-0와 함께 길을 찾는 웹게임입니다. 직접 관찰하고, 필요한 도움을 구체적으로 부탁하고, 설명과 실제 결과를 비교하며 탈출합니다.

[게임 플레이](https://blairmj.github.io/project-b0-chapter1/) · [학생 설문](https://blairmj.github.io/project-b0-chapter1/survey.html) · [교사용 분석](https://blairmj.github.io/project-b0-chapter1/analysis.html) · [분석 방법](https://blairmj.github.io/project-b0-chapter1/analysis-methods.html)

## 1. 게임 개요

| 항목 | 내용 |
| --- | --- |
| 대상 | 초등학교 5~6학년 |
| 장르 | 이야기 중심 퍼즐 어드벤처 / 방탈출 / 게임기반학습 |
| 시점 | 아이의 눈으로 보는 1인칭 |
| 핵심 경험 | 탐색 → 단서 확인 → 질문·부탁 → 조작 → 결과 확인·수정 |
| 교육 목표 | AI의 한계 이해, 근거 확인, 구체적인 지시, 오류 점검, 역할 분담, 사람의 최종 판단 |
| 실행 환경 | PC·태블릿의 웹 브라우저. 세로 화면 중심 UI |
| 구현 범위 | 4차시의 주요 공간, 별도 거울 관찰실, 중앙관리실 공략, 엔딩, 사후 설문·분석 |
| AI 동작 | 미리 정한 게임 규칙과 대화 분기. 실제 생성형 AI API·음성 인식·얼굴 인식·모델 학습은 사용하지 않음 |

### 이야기

아이와 B-0는 연구소에서 처음 만납니다. B-0는 모든 답을 아는 안내자가 아니며, 아직 보지 않은 물건이나 달라진 방의 상태를 확인해야 합니다. 아이는 연구소의 수업 영상과 비밀 일지에서 실수를 다루던 교육 방식을 발견하고, 중앙관리 AI AXIOM의 B-0 회수·초기화 명령에 맞서 함께 탈출할 방법을 찾습니다. 탈출 후에는 함께 공부하는 방으로 이어집니다.

이 표는 게임이 제공하는 학습 기회와 설계 목표입니다. 플레이만으로 해당 역량이 향상되었다고 판정하지 않습니다. 사후 자기평가·상황 판단·구체적인 행동 자료를 함께 살펴봅니다.

### 방 연결과 진행 조건

- 1층 복도에서 방을 선택해 탐색하며, 완료한 방에도 다시 들어갈 수 있습니다. 교육 실습실은 별도 차시 번호 없이 2차시 권역에 연결됩니다.
- 교육 실습실에서 기록 메모리를 챙겨야 기록 보관실에 입장할 수 있습니다. 컴퓨터에 메모리를 연결하면 비밀 일지 파일을 확인할 수 있습니다.
- 유리 관찰실과 거울 관찰실은 서로 다른 방입니다. 유리 관찰실을 마치면 거울 관찰실에 들어갈 수 있습니다.
- 새로 시작하는 모험은 거울 관찰실에서 휴대용 반사판을 챙긴 뒤 열쇠 보관함에서 계단실 열쇠를 얻습니다. 열쇠로 계단 차단을 해제하면 2층 중앙관리실로 올라갑니다.
- 거울방 추가 이전의 저장 기록은 기존 진행 경로를 유지합니다. 중앙관리실의 새 보스전은 반사판을 소지한 설정으로 진행합니다.

## 3. 주요 퍼즐과 안내 방식

### 유리 관찰실: 타이핑 없이 부탁 구성

1. 유리 너머의 실제 손잡이를 눌러 대상을 가리킵니다.
2. 움직임을 드래그로 보여 주거나 방향 버튼으로 고릅니다.
3. `한 번 움직이고 놓기`, `문이 열리면 놓기`, `내가 문턱을 지나면 놓기`, `내가 신호하면 놓기` 중 종료 조건을 정합니다.
4. B-0의 확인 문장을 보고 **이 부탁 보내기**를 누릅니다.

방향과 종료 조건은 처음부터 선택되어 있지 않습니다. 잘못 가리킨 손잡이나 위쪽 움직임도 실제 장치 반응으로 확인할 수 있습니다. 문 열림·실제 문턱 통과·명시적 신호를 구분하며, 신호 조건이면 문이 열려도 B-0가 기다립니다. 부탁을 바꾸려면 **부탁 멈추기** 또는 새 부탁을 사용합니다.

지시 초안 수정, 실행 당시 대상·방향·종료 조건, 이후 조사·종료 사건은 시각·요청 번호와 함께 해당 브라우저의 게임 진행에 저장됩니다.

### 거울 관찰실: 빛의 경로를 보며 수정

- 입장 안내창은 방이 돌아간 상황, 빛을 보내 문을 여는 목표, 다음 방에서 쓸 작은 거울을 짧게 소개합니다. **방 안내**에서 다시 볼 수 있습니다.
- B-0가 **빛 켜기 → 거울 A 조절 → 거울 B 조절 → 작은 거울 챙기기 → 나가기**를 한 단계씩 안내합니다. 실제로 확인한 상태에 따라 다음 행동을 고릅니다.
- 지금 눌러야 할 거울·버튼과 방향 조절 도구를 천천히 반짝여 강조합니다. 정답 방향은 미리 표시하지 않습니다. 동작 줄이기 설정에서는 움직임 없이 테두리를 강조합니다.
- **이전 메뉴얼**의 같은 방향 표시와 실제 빛 도착·문 열림 상태를 따로 보여 줍니다. 빛 받는 곳의 작은 앞쪽 구멍으로 빛이 들어와야 문이 열립니다.
- 빛을 켠 상태에서 거울을 돌리면 경로와 도착 상태가 즉시 바뀝니다. 방향 버튼·슬라이더를 사용할 수 있으며 매번 빛 버튼을 다시 누를 필요가 없습니다.
- 켜진 빛 기계는 밝은 중심, 청록색 빛 번짐, 주변 표면의 밝기로 작동 상태를 보여 줍니다. 성공 뒤 거울 A의 휴대용 반사판을 챙겨야 퇴장할 수 있습니다.
- 벽·바닥·천장과 B-0의 반사상을 WebGL로 표시합니다. 사용할 수 없는 환경에서는 같은 규칙의 배치도로 전환합니다. 동작 줄이기 설정에서는 관찰대의 회전 연출을 생략합니다.
- 바닥 클릭, ↑·↓ / W·S, 화면 이동 버튼으로 걷고 A·D로 옆걸음합니다. 방 경계와 거울·기계·B-0에 대한 충돌을 적용합니다. 상시 걷기 안내와 B-0 위 이름표는 표시하지 않습니다.

관찰한 장치, 시험 전 예상, 각도 변경, 실제 결과를 기록합니다. 빛을 켠 채 방향을 바꾼 시험은 `trigger: angle`, 빛 버튼으로 확인한 시험은 `trigger: button`으로 구분합니다. 방향이 실제로 바뀌지 않은 입력은 중복 시험으로 기록하지 않습니다.

### 중앙관리실: 기존 입체 공간에서 실시간 보스전

벽·바닥·천장, 원형 액시엄 장치와 B-0는 기존 중앙관리실의 CSS/WebGL 공간을 그대로 사용합니다. 별도의 평면 전투 화면으로 전환하지 않으며, 빈 곳을 끌어 둘러보거나 **전투 시점**으로 돌아올 수 있습니다. 보스전은 반사판을 이미 가진 상태로 시작합니다.

- 액시엄은 전투 시작 뒤 계속 광선을 발사합니다. 플레이어의 안전 팔찌에는 **보호막 에너지 100**, 액시엄에는 **HP 240**이 표시됩니다. 맞으면 보호막이 줄고, 반사 공격이 명중하면 액시엄 HP가 줄어듭니다. 두 번의 정해진 반격으로 끝나는 방식이 아닙니다.
- 액시엄의 공격은 충전 고리·발사 파동·주황색 에너지탄과 잔상으로 표시합니다. 피격 시 보호막 파동과 감소 숫자가 나타나고, 반사탄은 청록색으로 구분합니다. 이동 효과도 조사·메뉴 일시정지와 함께 멈춥니다.
- **반사판을 직접 끌어** 주황색 도착 표시로 옮깁니다. 끌고 있는 동안 중앙의 액시엄을 향해 자동으로 기울여 받아칩니다. 반사판에 초점을 둔 상태에서 방향키로도 위치를 옮길 수 있으며, **반사 공격** 버튼이나 스페이스를 누르면 연속 공격합니다. 기울이기 버튼은 각도를 5°씩 조절합니다.
- 액시엄의 발사점과 공격이 도착하는 위치는 **공격마다 무작위로 바뀝니다**. 발사점의 충전 빛과 주황색 원이 다음 경로를 예고하며, 이미 날아온 빛은 반사판을 따라오지 않습니다. 반사판이 실제 경로에서 벗어나면 보호막이 줄어듭니다.
- 출입 관리실 탈출, 교육 실습실의 메모리 획득, 거울 관찰실의 반사판 획득 때 **보조 배터리**를 하나씩 얻습니다. 보스전에서 사용하면 보호막 에너지 40을 회복합니다. 최대 세 개이며, 가득 찬 보호막에는 소모되지 않습니다.
- 기록 메모리를 단말기에 연결하면 액시엄의 전원과 카드 보관함을 확인할 수 있습니다. 단말기 조사·메뉴·브라우저가 숨겨진 동안 전투는 멈춥니다.
- 액시엄 HP가 0이 되면 공격이 멈추고 **출구가 즉시 열립니다.** 보관함에서 해제 카드를 꺼내 B-0의 가슴 슬롯에 넣은 뒤 바로 함께 나갑니다. 추가 수동 잠금쇠·손잡이 퍼즐은 없습니다.
- 보호막이 0이 되면 다시 도전할 수 있습니다. 재도전은 HP와 방에서 얻은 배터리를 복구합니다. 재접속은 HP·액시엄 HP·배터리·카드 상태를 유지하며 **전투 시작**을 다시 눌러 재개합니다.

이미 끝낸 통제실을 다시 플레이하려면 메뉴의 **현재 공간 다시 시작**을 사용합니다. 다른 방의 기록은 유지됩니다. 예전 카드 보스전 완료 기록도 B-0가 자유롭고 출구가 열린 상태로 이어집니다.

## 4. 조작과 공통 UI

| 조작 | 동작 |
| --- | --- |
| 빈 공간 드래그 | 방·복도 둘러보기 |
| 물건 클릭·탭 | 조사하거나 가능한 행동 선택 |
| 복도 바닥 클릭·탭 | 선택한 위치로 걷기 |
| 화면 방향 버튼 / 방향키·WASD | 공간에 맞는 이동·시선 전환 |
| 움직이는 물건 드래그 | 상자 이동, 손잡이·잠금쇠·연결 단자 조작. 대상별 버튼도 지원 |
| B-0에게 말하기 | 확인한 물건과 현재 상황에 맞는 질문·협력 요청 |
| 처음 위치로 | 현재 공간의 시점·배율 초기화. 퍼즐 진행은 유지 |
| 마우스 휠 / 상단 −·+ | 화면 확대·축소. 팝업 안에서는 내용 스크롤 |
| 메뉴 | 지도·소지품·사용법·기록·B-0 설정·시작 화면 등 |
| 상단 위치 드롭다운 → 설문 바로 가기 | 플레이 후 설문으로 이동 |

- 출입 관리실은 파노라마를 둘러보며 조사합니다. 나머지 공간은 상황에 맞게 걷거나 물건에 접근하고, 상자 위에 오르는 등의 이동을 제공합니다.
- 아이와 B-0의 말은 아래 말풍선에서 읽습니다. 메뉴·기록·설정·쪽지·풀이·그림 자료는 팝업으로 확인합니다.
- **메뉴 → B-0 설정**에서 `주인님·친구·탐험가`를 고르거나 원하는 호칭을 1~20자로 입력할 수 있습니다. 다음 대화부터 적용되며 같은 브라우저의 다음 접속에도 유지됩니다.
- 호칭 입력은 선택 설정입니다. 유리방의 부탁과 거울방의 방향 조절은 타이핑 없이 선택·드래그로 진행합니다.
- 자세한 조작은 **메뉴 → 사용법**에서 확인합니다.

### 개발 검토용 바로 이동

상단 위치 드롭다운으로 1·2층 복도와 각 방에 바로 갈 수 있습니다. **차시 앞으로 / 차시 끝으로**는 차시 시작·마무리 상태를 만드는 임시 기능입니다. 위치 이동은 소지품·퍼즐을 유지하지만, 차시 이동은 진행을 초기화하거나 완료 상태를 만들 수 있습니다. 임시 2층 이동은 실제 열쇠 획득·계단 해제를 대신 기록하지 않습니다.

정상 플레이와 교육적 수행을 검토할 때에는 **처음부터 시작**으로 진행하고, 바로 이동을 사용했다면 설문에서 검토용 이동 범위를 표시합니다.

## 5. 자동 저장과 플레이 기록

게임 진행과 학생 설문 초안은 브라우저의 `localStorage`에 저장됩니다. 현재 학생 응답을 자동으로 모으는 중앙 수집 서버는 없습니다.

| 자료 | 저장·활용 방식 |
| --- | --- |
| 게임 진행 | 방별 퍼즐, 소지품, 복도 위치, 열쇠·계단, 정전·비상 조명 등을 같은 브라우저에서 복원 |
| 유리방 행동 기록 | 부탁 구성·수정·실행·종료 사건을 게임 진행 안에 보관 |
| 거울방·보스전 요약 | 익명 플레이 ID로 설문 응답 파일에 필요한 수행 요약을 함께 포함 |
| 설문 초안 | 작성 중인 학생 응답 1건을 같은 브라우저에 자동 저장 |
| 분석 자료 | 불러온 파일을 해당 탭에서만 처리. 이어서 분석하려면 분석 묶음 JSON 저장 |
| B-0 호칭 | 게임 진행과 별도로 저장. 게임을 처음부터 시작해도 유지 |

- 방 이동과 **처음 위치로**는 퍼즐·정전 상태를 초기화하지 않습니다. 시작 화면의 **처음부터 시작**은 게임 진행을 초기화합니다.
- 브라우저·기기 간 동기화는 없습니다. 브라우저 저장소를 지우거나 다른 기기를 사용하면 기존 진행과 자동 연결이 이어지지 않습니다.
- 상세 게임 로그 전체가 설문으로 전달되는 것은 아닙니다. 현재 설문에는 거울방·최종 방의 선택된 수행 요약을 포함하며, 전체 대화와 사용자 호칭은 포함하지 않습니다.
- 거울방 저장 키는 `project-b0-reflection-v1`, 익명 플레이 ID는 `project-b0-play-id-v1`, 호칭 설정은 `project-b0-preferences-v1`입니다.

## 6. 플레이 후 설문과 교사용 분석

엔딩의 **모험 돌아보기 · 설문**, 상단 **설문 바로 가기**, 또는 [학생 설문 주소](https://blairmj.github.io/project-b0-chapter1/survey.html)로 접속합니다. 모든 문항은 건너뛸 수 있습니다.

### 설문 구성

현재 새 응답의 설문 버전은 **`b0-post-1.1`**입니다. 게임 버전명과 설문 도구의 버전명은 별개입니다.

| 구분 | 문항 수 | 내용 |
| --- | --- | --- |
| 학습 관련 자기평가 | 12 | 근거 확인, 구체적인 지시, 오류 점검·재시도, 역할 분담·자기 판단 각 3문항 |
| 새 상황에서의 판단 | 4 | 공부 방법·시간 자료 해석, 장치 요청의 종료 조건, 후속 시험 설계, 현재 정보에 따른 경로 판단 |
| 플레이 경험 | 4 | 재미, 재도전 의향, 조작 이해, 글 이해 |
| 선택 서술형 | 3 | 직접 확인한 근거, 방법을 바꾼 전후, 어려움·개선 의견 |

거울방을 플레이한 기기에서는 익명 플레이 ID, 완료·반사판 획득, 시험·관찰·예상 횟수, 한 장치·여러 장치를 바꾼 시험 횟수, 보스전의 받아치기 횟수·B-0 제어 해제 여부가 JSON 응답과 원자료 CSV에 포함됩니다. 기존 자료와 호환되는 `final.severed` 필드는 새 보스전에서는 해제 카드로 B-0의 잠금을 푼 상태를 뜻합니다. 빛을 켠 채 거울을 돌려 관찰한 결과도 시험 횟수에 포함하므로 빛 버튼을 누른 횟수와는 다릅니다.

이전에 작성하던 `b0-post-1.0` 응답은 기존 문항으로 이어지며, 분석 페이지도 이전 파일을 읽습니다. 상황 문항이 달라졌으므로 1.0과 1.1을 나누어 분석합니다.

### 수집·분석 절차

1. 학생이 마지막 화면에서 JSON 응답 파일을 저장합니다.
2. 교사가 정한 경로로 파일을 전달합니다. 설문 화면에서 자동 전송하지 않습니다.
3. [교사용 분석](https://blairmj.github.io/project-b0-chapter1/analysis.html)에서 여러 JSON 파일을 함께 불러옵니다. 파일은 서버에 업로드하지 않습니다.
4. 설문 버전·학급·플레이 범위를 확인하고, 자기평가·상황 판단·플레이 경험·수행 기록을 나란히 살펴봅니다.
5. 원자료·요약·서술형 코딩 CSV 또는 응답과 코딩을 포함한 분석 묶음 JSON을 저장합니다.

분석 화면은 문항군 평균·표본 표준편차·중앙값, 문항별 분포·결측, 상황별 정답률을 표시합니다. 같은 응답 ID의 파일은 최신 저장본을 유지하며, 미리보기 응답은 기본 분석에서 제외합니다. 서술형은 교사가 직접 코딩합니다.

이 설문은 시범 도구이며 검증된 표준 척도가 아닙니다. 자기평가·상황 판단·재미를 합친 총점은 만들지 않습니다. 시험 횟수나 조작 횟수도 이해도 점수로 곧바로 바꾸지 않습니다. 사후 자료만으로 학습 향상이나 게임의 인과 효과를 주장하지 않습니다.

[분석 방법과 문항표](https://blairmj.github.io/project-b0-chapter1/analysis-methods.html)에 수집 절차, 채점·결측 처리, 서술형 코딩, 해석의 한계와 후속 효과 검증 설계를 정리했습니다.
